# Contributing

Start with an issue that describes an IT failure the tool should explain. Include a minimal fictional example and the expected evidence. Keep changes read-only, dependency-light, and testable offline. Run `python -m unittest discover -s tests -v` before opening a pull request.

Never attach real company snapshots, credentials, internal addresses, or file manifests to a public issue. Reports are local troubleshooting evidence; redact them before sharing.
